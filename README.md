# 눈치챗 Frontend

기존 샌드·네이비 테마와 4개 언어(ko/en/vi/de)를 유지하면서 Railway API에 연결한 프런트엔드입니다. 앱 실행 경로에는 데모 사용자·샘플 워크스페이스·가짜 메시지 전송·확인자 전환·로컬 성공 처리가 없습니다.

## 실행

VS Code Live Server로 `login.html`을 열어 주세요. 권장 주소는 `http://127.0.0.1:5500/login.html`입니다. HTML 파일 더블클릭(`file://`)은 서버 CORS 정책상 지원하지 않습니다.

서버 주소는 `js/config.js`에서 관리합니다.

- REST: `https://backend-production-8acb6928.up.railway.app/api`
- STOMP: `wss://backend-production-8acb6928.up.railway.app/ws`
- 명세: `https://backend-production-8acb6928.up.railway.app/swagger-ui/index.html`

배포 시에는 실제 프런트 origin도 백엔드의 REST 및 WebSocket 허용 목록에 추가해야 합니다. 브라우저가 허용 여부를 결정하므로 프런트 코드로 CORS를 우회하지 않습니다.

## 사용 순서

1. **회원가입**에서 이름과 언어를 선택합니다. `POST /api/users`로 서버 사용자를 생성합니다. 메인 왼쪽 프로필의 **사용자 ID를 보관하세요**.
2. 다음 접속이나 다른 기기에서는 그 사용자 ID를 입력합니다. 서버에 이메일·비밀번호 로그인 API가 없어 비밀번호 입력창은 제거했습니다. `X-User-Id`는 해커톤용 식별 방식이며 일반적인 계정 인증은 아닙니다.
3. WORKSPACE 옆 **+**로 방을 생성합니다. 생성 후 자신을 서버 멤버로 등록합니다. 이미 있는 방은 같은 팝업에서 **워크스페이스 ID로 참여**합니다.
4. **팀원 추가** 팝업에서 방 ID를 확인하고 공유합니다. 가입한 친구의 사용자 ID를 입력해 서버 멤버로 직접 추가할 수도 있습니다. 이메일은 발송하지 않습니다.
5. 메시지는 서버 분석 후 전송합니다. 모호한 표현이 있으면 서버가 반환한 의도 후보 중 하나를 선택하거나 원문 그대로 전송합니다. 명세가 메시지 전체에 의도 하나만 지원하므로 표현별 의도를 따로 저장하지 않습니다.
6. 카드를 만들면 서버에 저장되고 채팅에 표시됩니다. 로그인한 본인만 확인할 수 있으며 보드 표시 여부는 서버 `status`를 따릅니다. 카드가 생성·수신된 위치를 기억하여 이후 메시지가 카드 아래에 표시됩니다. 새 기기에서 과거의 정확한 순서를 복원하려면 서버 카드 응답에 `createdAt`이 필요합니다.
7. **중간결산**은 보드 카드 중 영수증 전원 확인이 완료되지 않은 카드만 결산하는 새 흐름입니다. 현재 서버에 해당 생성/목록 API가 없어 생성은 연결 대기 상태이며, 기존 영수증 ID 조회·확인·이의 제출은 가능합니다. 필요한 명세는 [SETTLEMENT_API.md](SETTLEMENT_API.md)를 참고하세요.
8. 확정된 날짜 있는 카드/영수증 항목은 공용 캘린더에 등록할 수 있습니다. 개인 투두는 서버에 저장하며 추가·내용 수정·완료·삭제를 지원합니다. 캘린더 등록 시 투두까지 자동 생성한다고 가정하지 않습니다.

## 서버가 관리하는 상태

- 메시지·카드·멤버·영수증·일정·투두는 API에서 조회합니다. API 실패 시 로컬 성공 데이터로 대체하지 않습니다.
- 서버 사용자 ID와 이 브라우저에서 열었던 방 ID, 확인한 영수증 ID만 localStorage에 보관합니다. 채팅/카드 내용은 저장하지 않습니다. 표시 순서 유지를 위해 방별 메시지·카드 ID 순서만 별도로 보관합니다. 이전 데모 저장 데이터는 읽지 않습니다.
- 실시간 `/topic/rooms/{roomId}` 이벤트를 받으면 서버 내용을 다시 조회합니다. 10초 간격 조회도 병행하므로 WebSocket이 끊겨도 서버 상태를 확인할 수 있습니다. 숨겨진 탭은 주기 조회를 쉬고, 복귀하면 재조회합니다.
- 실패한 작성 요청은 입력값을 유지합니다. 쓰기 요청을 자동 재시도하지 않습니다. 응답 시간 초과는 서버 처리 여부가 불확실하므로 재전송 전에 조회해야 합니다.
- 방 생성 성공 후 멤버 추가만 실패한 경우 같은 팝업에서 다시 제출하면 생성된 방에 참여를 재시도합니다.

## 현재 API 제약

다음 기능은 2026-11-15에 조회한 Swagger에 없어 임의 구현하지 않았습니다.

| 없는 API/필드 | 현재 동작 |
| --- | --- |
| 이메일·비밀번호 인증 | 가입 및 기존 사용자 ID 조회로 접속 |
| 내 방 목록 조회 | 같은 브라우저에서 열었던 방 ID들을 재조회하고 서버가 현재 사용자를 멤버로 확인한 방만 표시. 다른 기기에서는 방 ID로 참여 |
| 방 탈퇴·멤버 제거 | 중간결산 오른쪽에 나가기 버튼·안내 팝업 표시. 실제 탈퇴는 API 미지원으로 비활성화. 로그아웃은 서버 멤버십을 변경하지 않음 |
| 이메일 초대·수락·취소 | 사용자 ID로 멤버 추가 / 방 ID로 참여 |
| 카드 종류·여러 담당자 | 종류 필터 제거, 담당자 1명 선택 |
| 영수증 목록·진행 중 회의 조회 | 브라우저가 알고 있는 ID 및 수신한 종료 이벤트 이용. 기존 영수증은 ID로 조회 가능 |
| 영수증 수정·날짜 재수정 | 확인·이의 제기만 제공 |
| 사용자 언어 수정 | 가입 언어는 서버 저장. 이후 화면 언어 변경은 계정별 브라우저 설정 |
| 투두 마감일·워크스페이스 연결 | 제목·완료 상태만 저장, 사용자 전체 투두 표시 |
| 공지 해석·질문·메일 작성 | 기존 로컬 예시 도구 제거 |

방 목록과 회의/영수증 목록 API를 추가하면 브라우저의 ID 목록 의존성을 없앨 수 있습니다. 여러 기기에서 진행 중인 회의를 이어받는 기능도 활성 회의 조회 API가 필요합니다.

## 파일 구조

- `js/config.js`, `js/user-api.js`: 서버 설정, 요청·오류·타임아웃, 사용자 생성/조회
- `js/state.js`: 서버 조회 결과와 방 참조, 최신 조회만 적용
- `js/sidebar.js`, `js/invitations.js`: 방 생성/참여·멤버 추가
- `js/chat.js`, `js/meaning.js`: 메시지·분석 결과 선택
- `js/board.js`: 서버 카드 생성/확인/보드
- `js/tools.js`: 서버 회의·영수증·캘린더·투두
- `js/realtime.js`: STOMP 구독·재연결·주기 조회
- `js/login.js`, `script.js`: 로그인·메인 초기화
- `js/i18n.js`, `js/locales/`: UI 번역. 자세한 규칙은 [I18N.md](I18N.md)
- `css/api.css`: 연결 오류와 서버용 필드 스타일

## 검증

Node.js와 Windows Edge가 설치된 환경에서 프로젝트 루트에서 실행합니다.

```powershell
npm.cmd exec --yes --package=playwright -- node tests/api-integration.cjs
```

테스트는 `tests/openapi.json`의 실제 Swagger 스냅샷으로 요청 엔드포인트와 필드를 검사하고, 테스트 안에서만 네트워크 응답을 대체합니다. 앱에는 mock 모드가 없습니다. 두 사용자·실제 ID 헤더·방 생성 재시도·채팅/카드/영수증/캘린더/투두·실패 입력 보존·STOMP 이벤트 반영·로그인·언어 유지·모바일을 확인합니다.

실서버에서는 브라우저 origin `http://127.0.0.1:5500`에서 CORS 요청 성공, `/api/health`의 `UP`, STOMP `CONNECTED`를 확인했습니다. 실서버에 테스트 사용자·방·메시지를 생성하지 않았으며 실제 서버 쓰기/LLM 결과까지의 통합 검증은 사용자 계정으로 진행해야 합니다.
## 전송 전 의도 확인 UI

엔터/보내기 → 서버 분석 → 모호한 표현이 있을 때 입력창 위 바텀시트로 뜻 선택 → 선택한 의도로 전송합니다. 닫기/Escape는 초안을 유지하고 편집으로 돌아갑니다. 전송 실패 시 시트에서 오류를 표시하고 재시도할 수 있습니다.

보낸 메시지는 발신자에게 원문으로 표시하고, 수신자는 서버 번역과 발신자가 확인한 뜻 배지·원문 토글을 봅니다. 번역 미리보기/비교 문장은 서버 필드가 없어 생성하지 않습니다.
