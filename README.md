# 눈치챗 프런트엔드 파일 구성

`test.html`을 브라우저에서 직접 열면 됩니다. 별도 빌드 과정은 없습니다.

## CSS

`style.css`는 스타일 파일을 순서대로 불러오는 진입점입니다.

- `css/base.css`: 색상 변수, 기본 글꼴, 요소 기본값
- `css/sidebar.css`: 전체 화면 틀, 사이드바, 워크스페이스, 프로필
- `css/avatars.css`: 팀원 아바타와 색상
- `css/header.css`: 상단 헤더, 팀원 목록, 공통 버튼
- `css/chat.css`: 채팅 영역, 메시지, 입력창
- `css/board.css`: 합의 보드와 필터
- `css/dialog.css`: 의미 확인 모달, 입력 필드, 토스트
- `css/responsive.css`: 화면 크기별 대응과 채팅방 상단 버튼 스타일

## JavaScript

`test.html`의 스크립트 순서는 공통 파일 → 기능 파일 → `script.js`입니다.
로컬 HTML 실행을 지원하기 위해 일반 스크립트를 사용하며 공통 상태와 함수를 공유합니다.

- `js/utils.js`: DOM 선택과 HTML 이스케이프
- `js/state.js`: 사용자·워크스페이스별 로컬 데이터 저장
- `js/toast.js`: 안내 메시지 표시
- `js/chat.js`: 채팅 렌더링, 전송, 입력 이벤트
- `js/meaning.js`: 의미 선택과 모달 이벤트
- `js/sidebar.js`: 워크스페이스 생성·선택, 팀원 표시, 모바일 메뉴
- `js/board.js`: main 합의 카드 팝업·채팅 확인·전원 확인 후 보드 고정
- `script.js`: 각 기능 초기화

합의 카드는 채팅에 먼저 올라가며 현재 워크스페이스의 모든 팀원이 확인해야 보드에 고정됩니다. 데모 확인자 선택은 로컬 시뮬레이션이며 실제 인증을 대신하지 않습니다.

## 새 기능

- `css/workspace.css`: 로그인 화면의 눈치챗 로고, 워크스페이스·초대 UI, 모바일 보드
- `js/invitations.js`: 로컬 초대 준비·취소·데모 참여 수락
- WORKSPACE 옆 + 버튼으로 공간을 만들면 즉시 해당 공간이 선택됩니다.
- 공간마다 메시지, 팀원, 초대 목록이 따로 저장됩니다.
- 데이터는 사용자별 localStorage에 저장됩니다. 새로고침 후에도 워크스페이스·대화·카드·영수증·일정·투두를 유지합니다.
- 초대는 실제 이메일을 보내지 않습니다. ‘데모: 참여 수락’ 버튼으로 팀원 추가를 테스트할 수 있습니다.
- 서버 API·WebSocket·실제 인증은 아직 연결하지 않았습니다. 가입 시 언어 선택과 사용자 API 어댑터는 I18N.md를 참고하세요.

## main 카드 기능 통합

- `css/agreement.css`, `css/dialog.css`: main의 카드 UI와 생성 팝업을 반영합니다.
- 워크스페이스마다 카드와 확인 현황을 별도로 저장합니다. 새로고침 후에도 유지됩니다.
- 담당자 및 데모 확인자는 실제 선택된 워크스페이스의 멤버 목록을 사용합니다.
- 확인은 이름 대신 사용자 ID로 구분합니다. 모든 현재 멤버가 확인해야 보드에 표시합니다.
- 새 멤버가 참여하면 해당 멤버가 확인할 때까지 보드 고정이 해제됩니다.
- `js/workspace-leave.js`: 나가기 확인, 다음 워크스페이스 선택, 마지막 공간의 빈 상태를 처리합니다.
- 기존 실험용 카드 데이터는 보존하되 새 카드 스키마(schema: 2)와 분리합니다.
## 공식 샌드 · 네이비 테마

- `css/tokens.css`: 제공된 handoff ZIP의 공식 색상 토큰
- `css/theme.css`: 메인 화면 테마 (기존 레이아웃과 기능 유지)
- `css/login-theme.css`: 로그인 화면 테마
- `css/brand.css`: 공식 PNG 로고의 표시 영역과 크기
- `assets/brand/`: 제공된 원본 아이콘, 밝은 배경용/어두운 배경용 가로형 PNG
- 테마는 기존 CSS 뒤에 불러옵니다. 기능 JS와 로그인 처리 코드는 변경하지 않았습니다.

## ZIP 기능 추가: 현재 메인 디자인 유지

`nunchi_chat_handoff.zip`의 01~12 화면을 기능 참고로 사용했습니다. 고정 크기 시안으로 메인 화면을 교체하지 않았으며, 기존 로그인·로고·워크스페이스·초대·나가기·채팅·카드 작성 기능을 유지합니다. 제목과 내용은 자동 입력하지 않습니다.

- `js/tools.js`: 합의 영수증, 수신 화면 미리보기, 캘린더, 투두, 공지 해석, 질문·메일 초안.
- `css/tools.css`: 새 도구 화면에 적용되는 스타일. 메인 배치와 테마는 유지합니다.
- 현재 페이지의 워크스페이스 안에 있는 `tools`에서 데이터를 관리합니다. 사용자별 브라우저 저장소에도 기록합니다.

### 사용 순서

1. 채팅에서 합의 카드를 작성하고 팀원별로 확인합니다. 모두 확인한 카드만 보드에 고정됩니다.
2. 상단 **중간 결산**를 누르면 팀원 모두가 확인해 합의 보드에 고정된 카드만 모아 영수증을 만듭니다. 채팅에서 확인 대기 중인 카드와 보류 메시지는 제외합니다. 영수증은 별도로 항목별 확인을 받습니다.
   이미 영수증에서 전원 승인한 동일 내용의 카드는 새 영수증에서 제외합니다. 기존 영수증 기록은 유지하며, 카드 내용·마감일 변경이나 이의 제기로 재확인이 필요하면 다시 포함합니다. 새로 확인할 항목이 없으면 빈 영수증을 만들지 않습니다.
3. **데모 확인자**를 바꾸며 각 항목을 확인하거나 이유를 입력해 이의를 남깁니다. 이의가 있는 카드는 합의 보드에서도 확정으로 표시하지 않습니다.
4. **날짜 정규화 · 수정 · 다시 확인 요청**에서 날짜를 수정하면 이전 동의가 초기화됩니다. 날짜는 월 이름과 요일을 포함해 표시합니다. 보류된 논의는 확정 일정으로 등록하지 않습니다.
5. 모든 항목의 확인이 끝나면 확정 도장이 표시됩니다. **공용 캘린더·개인 투두에 등록**하면 일정과 담당자별 할 일이 생성됩니다. 같은 항목을 반복 등록해도 중복되지 않습니다.
6. 공용 캘린더에서 이전·다음 달과 오늘로 이동하거나 일정을 눌러 원본 영수증을 엽니다. 투두는 데모 확인자별로 확인·추가·삭제할 수 있습니다.
7. 공지 해석에 원문을 붙여 넣으면 `가급적`, `내외`, `자유롭게`를 강조하고 설명합니다. 확인할 질문을 저장하고 메일 초안을 복사하거나 공지 내용을 팀 채팅에 공유할 수 있습니다.

수신 화면 미리보기는 발신 화면과 선택한 팀원의 수신 화면을 나란히 표시합니다. 영수증은 한국어·English·Tiếng Việt·Deutsch 화면 언어 설정과 연동합니다. 사용자 작성 내용의 실제 번역, AI 분석, 이메일 전송, 실시간 다중 사용자 서버는 연결되어 있지 않습니다. 실제 인증 대신 기존 데모 확인자를 사용합니다.

기존에 등록한 일정의 영수증에 이의가 생기거나 새 팀원이 참여하면 확인이 끝날 때까지 해당 일정·자동 투두를 숨깁니다. 날짜를 수정하면 이전 자동 일정·투두를 제거하고 재확인 후 다시 등록하도록 합니다. 직접 추가한 투두는 유지합니다.

### 검증

프로젝트 폴더의 PowerShell에서 실행합니다. 외부 패키지는 필요하지 않습니다.

```powershell
Get-Content -Raw tests/workspace-tools.test.cjs | node
```

초기 실행, 전원 확인, 이의 제기, 날짜 수정과 동의 초기화, 일정·투두 중복 방지, 새 팀원 참여, 새로고침 유지·이전 저장 기록 보존, 워크스페이스 분리, 공지 강조, 메일 초안, 화면 전환, 폼 입력 보존을 검증합니다. 실제 브라우저 화면의 시각적 비교는 별도 확인이 필요합니다.
